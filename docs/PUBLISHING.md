# Подпись установщика и публикация в Chrome Web Store

## Подпись установщика

Подпись убирает предупреждение SmartScreen и снижает число ложных срабатываний антивирусов. Подписывается только `VPN-Terminal-Setup-windows-*.exe`.

Варианты сертификата:
- **Azure Trusted Signing (Artifact Signing)**: около 10 долларов в месяц, сертификат создаётся на проверенную организацию или физлицо. Доступность зависит от страны.
- **SignPath Foundation**: бесплатная подпись для открытых проектов, нужна заявка.
- **Обычный сертификат подписи кода (OV)** у DigiCert, Sectigo, SSL.com и других. Репутация в SmartScreen накапливается постепенно.
- **EV-сертификат**: дороже, репутация в SmartScreen сразу. Выдаётся на токене или в облачном HSM.

Подпись в CI (файл `.github/workflows/build.yml`) работает, если сертификат лежит в формате PFX:

1. Закодируйте сертификат: `base64 -w0 cert.pfx`.
2. В репозитории откройте Settings → Secrets and variables → Actions и создайте секреты `WIN_CERT_PFX_BASE64` (результат шага 1) и `WIN_CERT_PASSWORD`.
3. Следующая сборка подпишет оба Windows-файла через `osslsigncode` и поставит метку времени.

Для облачных сервисов (Azure, SignPath) вместо шага подписи в workflow подключается их action по документации сервиса.

## Chrome Web Store

1. Создайте аккаунт разработчика на https://chrome.google.com/webstore/devconsole, разовый взнос 5 долларов, включите двухфакторную защиту.
2. Скачайте из релиза `vpn-terminal-extension-store.zip`. В нём манифест без поля `key`: магазин присваивает расширению собственный ID.
3. В консоли выберите «Добавить новый элемент» и загрузите архив.
4. Заполните карточку: описание, скриншоты 1280×800, значок 128×128, категорию.
5. Вкладка «Конфиденциальность»:
   - обоснование разрешений: `proxy` и `webRequest` для направления трафика через VPN, `nativeMessaging` для связи с локальным хостом, `privacy` для защиты от утечки WebRTC, `storage` для настроек, `<all_urls>` для маршрутизации любых сайтов;
   - заявление, что удалённый код не используется;
   - ссылка на политику конфиденциальности (достаточно страницы в репозитории: данные не собираются, обращения идут только к перечисленным в `SECURITY.md` адресам).
6. Отправьте на проверку. Из-за `<all_urls>` и `proxy` проверка занимает от нескольких дней до пары недель.

### Связь магазинной версии с хостом

ID расширения из магазина отличается от ID разработческой версии. Хост принимает оба:

1. После создания элемента скопируйте его ID из консоли.
2. В репозитории создайте переменную Actions `STORE_EXTENSION_ID` (Settings → Secrets and variables → Actions → Variables).
3. Следующая сборка вшивает этот ID в установщик, и в `allowed_origins` манифеста хоста появляются оба ID.

Расширение из магазина обновляется само. Установщик с хостом пользователь обновляет вручную.

### Яндекс Браузер

Яндекс Браузер ставит расширения из Chrome Web Store: пользователю достаточно открыть страницу расширения и нажать «Установить», затем запустить установщик хоста.
