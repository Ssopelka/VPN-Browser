# Безопасность

## Модель защиты

- Локальный прокси слушает только `127.0.0.1`, порт выбирается случайно, доступ требует случайные логин и пароль. Они передаются расширению через native messaging и хранятся в `storage.session`.
- Расширение отдаёт пароль только своему прокси.
- Хост запускается только из расширения с фиксированным ID, который задан полем `key` в манифесте и списком `allowed_origins`.
- У ядра нет HTTP-API: статистика передаётся хостом напрямую.
- Kill-switch блокирует проксируемые запросы, пока VPN не вернётся или пользователь не отключится сам.
- Настройки проходят проверку по белому списку ключей и типов, сообщения принимаются только от страниц самого расширения.
- Подписки и списки доменов скачиваются с ограничением размера и времени. В расширении действует строгая CSP.
- Ядро вшито в установщик и не загружается из сети.

## Ограничения

- Ссылка-подписка и ключ хранятся в `chrome.storage.local` в открытом виде, как и у большинства расширений.
- Подписку по `http://` стоит заменить на `https://`.
- Расширению нужны `<all_urls>` и `webRequest` для проксирования. Содержимое страниц оно не читает.
- Внешние запросы: `api.ipify.org` (показ IP), `speed.cloudflare.com` (замер скорости), `cp.cloudflare.com` (проверка связи через VPN), `raw.githubusercontent.com` и `community.antifilter.download` (списки блокировок).
- Установщик не подписан.

## Сообщить об уязвимости

Откройте приватное уведомление через раздел Security репозитория (Report a vulnerability). Не публикуйте детали в открытых issue.

## Проверка

`go test -tags with_utls ./host` запускает проверки разбора ссылок, native messaging, сквозной тест «клиент, сервер Shadowsocks, веб-сервер», отказ прокси без логина или с неверным паролем.
